## Context

本链路需要在不破坏既有 L0->L4 诊断连续性的前提下，逐波次将 MM 识别能力迁入 Rust owner。关键风险在于：字段新增后 schema 与消费方不一致、以及提案与实现脱节。

## Design

1. 父提案仅持有治理约束，不直接承载运行时代码。
2. 每个子提案必须明确：
   - 变更字段清单
   - 影响模块
   - 验证命令
3. 每个子提案执行顺序固定，禁止并行跳步。

## Consistency Rule

子提案完成前必须核对以下三处一致：

1. OpenSpec spec 字段定义
2. Rust/Python runtime 合同字段
3. CSV/payload 暴露字段

任一不一致则不得推进到下一个子提案。
